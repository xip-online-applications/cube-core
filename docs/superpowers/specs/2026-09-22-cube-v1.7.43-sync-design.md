# Sync cube-core with upstream Cube v1.7.43

## Context

`cube-core` last synced cleanly with upstream `cube-js/cube` at tag `v1.7.33`
(see [2026-09-03-cube-v1.7.33-sync-design.md](2026-09-03-cube-v1.7.33-sync-design.md)
and its [plan](../plans/2026-09-03-cube-v1.7.33-sync.md) for that effort).
`v1.7.33` is still the exact git merge-base between `master` and upstream —
confirmed via `git merge-base HEAD v1.7.43` returning the `v1.7.33` commit
exactly. Upstream has since moved 151 commits ahead to `v1.7.43`
(https://github.com/cube-js/cube/releases/tag/v1.7.43). This spec covers
bringing the fork up to date with `v1.7.43` while preserving all custom
functionality.

As before, the `upstream` git remote is configured over SSH
(`git@github.com:cube-js/cube.git`) but this machine has no working SSH key
for it. HTTPS access to the same repo (`https://github.com/cube-js/cube.git`)
works and is used for all investigation and merge work here.

## Investigation findings

- **Divergence point**: merge-base of `HEAD` (branch `claude/cube-upstream-sync-bb42ea`,
  itself branched from `master` at commit `e13544093`) and upstream `v1.7.43`
  is exactly the `v1.7.33` tag commit (`465fdf160665cf78e2bee9c964719a96e9a55d12`).
- **Real custom diff is 105 files** (full list in Appendix A), comparable in
  size to the 87-file inventory from the last sync — same areas, plus a few
  additions landed since: Datadog `time_in_queue`/`query_duration` dispatch
  in `cubejs-query-orchestrator` (`QueryQueue.ts`, `QueryCache.ts`), a
  Rust/Tesseract `LIKE`-instead-of-`starts_with` filter change
  (`rust/cube/cubesqlplanner/**/filter/operators/like.rs` and related), and
  disabling two more upstream workflow files (`bridge-tests.yml`,
  `claude-code-review.yml`, `claude-code.yml`, `cube-cli.yml` → `.bak`) plus
  a Docker source-path fix. No new packages were added since `v1.7.33` (the
  fork still has exactly `cubejs-event-emitter` and `cubejs-tracer` as
  upstream-absent packages).
- **Raw diffstat vs. `v1.7.43`** is 1690 files / ~52.8k insertions / ~106.4k
  deletions — dominated by upstream's own churn (docs-mintlify content,
  `yarn.lock`, generated/compiled output) rather than conflicting fork
  customizations. The deletions are large because a chunk of upstream's own
  files were renamed/restructured over 151 commits.
- **Upstream commit volume**: 151 commits between `v1.7.33` and `v1.7.43`
  (vs. 615 for the `v1.6.49` → `v1.7.33` sync) — a much smaller merge in
  practice, even though the calendar span covers 10 patch releases.
- No orphaned Rust build-artifact directories this time — that cleanup was
  already done and is committed on `master` (`.gitignore` already excludes
  `/rust/cubesqlplanner/` and `/rust/cubeorchestrator/` at the top level;
  the real source remains under `rust/cube/cubesqlplanner` and
  `rust/cube/cubeorchestrator`, confirmed present in Appendix A).

## Custom functionality inventory (from the 105-file diff)

Same core areas as the `v1.7.33` sync, still intact, plus what's changed
since:

- **`cubejs-event-emitter`** / **`cubejs-tracer`** (packages with no
  upstream equivalent): unchanged since last sync.
- **`cubejs-api-gateway`**: WebSocket subscription server
  (`ws/subscription-server.ts`, `ws/local-subscription-store.ts`), extended
  `meta`/`metaExtended` with `preAggregations`, graphql/query adjustments —
  unchanged in intent since last sync.
- **`cubejs-schema-compiler`**: custom granularities
  (`convertToGranularityInSeconds`/`granularityToSeconds`), case-insensitive
  filter operators (`iStartsWith`, `likeIgnoreCase`), Postgres `convertTz`
  fix, pre-aggregation-by-time-dimension matching — unchanged in intent.
- **`cubejs-server-core`**: event emitter/tracer wiring — unchanged in
  intent.
- **`cubejs-query-orchestrator`**: `QueryCache`/`QueryOrchestrator`
  adjustments for the above, **plus new since `v1.7.33`**: Datadog
  `time_in_queue` and `query_duration` metric dispatch in `QueryQueue.ts`
  and `QueryCache.ts` (PR #89, commit `95732eca2`).
- **`cubejs-backend-native`**, Rust (`rust/cube/cubeorchestrator`,
  `rust/cube/cubesqlplanner`, `rust/cubestore`): native module loading path
  fixes, `iStartsWith`/`LIKE` filter operator in the Tesseract planner —
  **new since `v1.7.33`**: the filter now generates `LIKE` instead of a
  `starts_with` scalar function call for the `iStartsWith`-family operators
  (`filter/operators/like.rs`, `typed_filter.rs`, `sql_templates/plan.rs`,
  plus a new test in `tests/filter/to_sql.rs`) — a performance-motivated
  change per the `use-like-instead-of-starts_with` branch merged into
  `master`.
- **`cubejs-docker`**, `.dockerignore`, `.github/workflows/*`: custom
  Dockerfiles and CI workflows — **new since `v1.7.33`**: a Docker
  source-path fix (`fix(docker): correct Rust source paths for
  cubeorchestrator/cubesqlplanner in dockerignore and Dockerfiles`, commit
  `511c5da20`) and four more upstream workflows disabled to `.bak`
  (`bridge-tests`, `claude-code-review`, `claude-code`, `cube-cli`).
- **`cubejs-client-core`**, **`cubejs-playground`**,
  **`cubejs-cubestore-driver`**, **`cubejs-backend-shared`**: unchanged in
  intent since last sync.
- Root **`tsconfig.base.json`**, **`tsconfig.json`**, **`package.json`**,
  **`yarn.lock`**, **`.gitignore`**: fork-specific config/dependency
  changes, including the Rust build-artifact `.gitignore` entries added in
  the last sync.

All of the above must still work after this sync; see Testing.

## Approach

### 1. Create the sync branch and merge upstream

Work happens directly on the current branch (`claude/cube-upstream-sync-bb42ea`,
already isolated in its own worktree and already branched from `master`) —
no separate `sync/v1.7.43` branch is needed since this branch already serves
that purpose. Rename/PR title will reflect the sync explicitly regardless of
branch name.

```bash
git fetch https://github.com/cube-js/cube.git v1.7.43
git merge FETCH_HEAD -m "Merge upstream cube-js/cube v1.7.43"
```

Resolve conflicts file by file, using the same general rule as last time:
where upstream changed code we haven't touched, take upstream's version.
Where our fork added something upstream doesn't have, keep ours additively.
Where both sides changed the *same* lines, preserve the fork's custom
behavior while adopting upstream's surrounding refactor/structure — never
silently drop fork-specific behavior to resolve a conflict.

Expected hotspots, in rough order of conflict risk (same areas as last
time, now with two smaller additions):

- `yarn.lock` — full conflict expected; do **not** hand-merge, regenerate
  via `yarn install` at the end.
- `packages/cubejs-api-gateway/src/ws/*`, `gateway.ts` — subscription
  server / extended meta.
- `packages/cubejs-schema-compiler/src/adapter/*`,
  `compiler/CubeSymbols.ts` — granularity and filter-operator
  customizations.
- `packages/cubejs-query-orchestrator/src/orchestrator/QueryQueue.ts`,
  `QueryCache.ts` — now carries the Datadog dispatch on top of the
  pre-existing cache customizations; extra care needed since this file
  changed on the fork *after* the last sync, not just at sync time.
- `packages/cubejs-server-core/src/core/*` — event emitter/tracer wiring.
- `.github/workflows/*`, `packages/cubejs-docker/*`, `.dockerignore` —
  preserve `.bak` disabling intent; note 4 more files are now disabled than
  last sync's Appendix A.
- `rust/cube/cubesqlplanner/**` — now includes the `LIKE`-vs-`starts_with`
  filter change on top of the original `iStartsWith` customization; likely
  the highest-effort conflict given active upstream Tesseract development.
- New packages `cubejs-event-emitter`, `cubejs-tracer` — should merge in
  without conflict (no upstream equivalent).

### 2. Version bump

Update `lerna.json` and root `package.json` version to `1.7.43`, following
the repo's convention (`cube 1.7.33` commit precedent from the last sync).

### 3. Build and automated validation

```bash
yarn install        # regenerates yarn.lock cleanly post-merge
yarn tsc
yarn build
yarn lint
```

Rust: `cargo check` for `rust/cube`, `rust/cubesql`, `rust/cubestore`
workspaces; run `cargo test -p cubesqlplanner -p cubeorchestrator` given the
Tesseract filter changes are the highest-risk area this time.

Then run `yarn test` in each touched package per the inventory above.

### 4. Manual smoke check

Same four flows as last sync, since the same custom behaviors are at stake:
WebSocket subscriptions, a custom minute-level granularity query,
`iStartsWith`/case-insensitive filtering (now verify it still produces
correct results with the `LIKE`-based Rust implementation, not just the JS
side), extended `meta` endpoint with `preAggregations`.

### 5. Push and open a PR

Push the branch to `origin` and open a PR into `master`, following the same
PR description structure as the `v1.7.33` sync.

## Out of scope

- Fixing SSH access to the `upstream` remote (HTTPS is sufficient).
- Any new features or refactors beyond what's needed to reconcile the merge
  and keep existing custom functionality working.
- Re-enabling any `.bak` GitHub workflow files.
- Re-running the full `docs-mintlify` content reconciliation by hand file by
  file — this directory is large, mostly upstream content with no fork
  customizations recorded in the custom-file inventory; take upstream's
  version wholesale on any conflict there.
